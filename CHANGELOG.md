# Versioning Strategy

WBF uses the following versioning model:

| Version Type | Description |
|--------------|-------------|
| **Major** | Significant architectural changes, framework restructuring, or breaking changes |
| **Minor** | New specifications, templates, standards, guides, or framework capabilities |
| **Patch** | Documentation improvements, corrections, formatting updates, and minor clarifications |

# Release Guidelines

Every release should include, where applicable:

## Added

New capabilities introduced.

Examples:

- New specifications
- Templates
- Guides
- Standards
- Examples

---

## Changed

Improvements to existing framework components.

Examples:

- Updated guidance
- Architecture improvements
- Repository restructuring
- Documentation enhancements

---

## Deprecated

Features or documents scheduled for removal.

Deprecated content should include migration guidance whenever practical.

---

## Removed

Items removed from the framework after deprecation.

---

## Fixed

Corrections including:

- Broken links
- Formatting
- Documentation errors
- Cross-reference issues
- Terminology corrections

---

## Security

Security-related improvements, governance enhancements, or vulnerability documentation affecting the framework or supporting tooling.

---

# Maintaining the Changelog

When updating this document:

- Record notable changes only.
- Group changes by release.
- Keep entries concise and meaningful.
- Reference related issues or pull requests where appropriate.
- Update version numbers consistently across the repository.
- Maintain reverse chronological order (newest release first).
