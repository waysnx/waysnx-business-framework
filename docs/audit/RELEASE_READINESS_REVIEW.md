### 7.2 Public Core (current)

The default `GITHUB_TOKEN` of the runtime repository is enough. Its access applies to the runtime repository itself, and the public Core repository can be cloned anonymously. No secret is needed. Fork pull requests work too.

### 7.3 If Core becomes private

- `GITHUB_TOKEN` **cannot** read another private repository, so the checkout fails. The adapters report `CONFIGURATION ERROR`, which is correct but blocks every run.
- Options:
  - (a) a fine-grained personal access token, scoped to Core, *Contents: read-only*, stored as `WBF_CORE_READ_TOKEN` in both runtime repositories
  - (b) a GitHub App with read access to Core and `actions/create-github-app-token`
  - (c) a read-only deploy key and `ssh-key:`

  Pass it with `token: ${{ secrets.WBF_CORE_READ_TOKEN }}` (or `ssh-key:`) on the Core checkout step.
- Pull requests from forks do not receive secrets. Under a private Core they would fail with `CONFIGURATION ERROR`. Decide whether to accept that (strict) or to run conformance for fork PRs only after a maintainer re-runs it.
- Token rotation and ownership need an owner. Option (b) avoids personal tokens.

### 7.4 Hardening recommended at activation

1. **Tag immutability.** Git tags can be moved or deleted. Protect `conformance-v*` with a repository ruleset (no update, no deletion). Optionally record the tag's commit SHA in the workflow and verify it after checkout.
2. **Action pinning.** `shivammathur/setup-php@v2` is a third-party action. Pin it, and optionally the GitHub-owned actions, to a full commit SHA.
3. **Triggers.** Use the same `push`/`pull_request` branches as `ci.yml`. Keep `workflow_dispatch` for manual re-runs.
4. **Parity with `ci.yml`.** Laravel conformance runs PHP 8.3 only, while `ci.yml` uses 8.3 and 8.4. Consider the same matrix. Node conformance has no `concurrency` group; Laravel's does.
5. **Branch protection.** Make the conformance job a required check only after the first green run against the tag.
