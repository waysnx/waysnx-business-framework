# KNOWN LIMITATIONS

> **Current limitations, scope boundaries, and future enhancements for the WaysNX Business Framework (WBF).**

---

# Introduction

The **WaysNX Business Framework (WBF)** is an evolving engineering framework designed to improve software development through structured business analysis, architecture, documentation, governance, and quality practices.

While the framework provides a strong foundation, it is actively evolving. This document outlines the current limitations, identifies areas that are intentionally out of scope, and highlights planned improvements to help users adopt WBF with clear expectations.

Being transparent about limitations allows organizations to make informed decisions and helps guide future contributions.

---

# Current Scope

The current release primarily focuses on establishing the foundation of the framework, including:

- Business Framework principles
- Repository structure
- Documentation standards
- Governance model
- Review methodology
- Engineering guidelines
- Specifications
- Templates
- Examples
- Best practices

The emphasis is on creating a consistent and maintainable engineering framework rather than delivering implementation-specific solutions.

---

# Current Limitations

## Limited Reference Implementations

WBF primarily defines **how software should be planned and documented**.

It currently contains limited reference implementations or sample applications.

Future releases may include:

- Sample repositories
- Reference architectures
- End-to-end examples
- Demonstration projects

---

## Technology-Specific Guidance

WBF intentionally avoids prescribing specific technologies.

As a result, it does not currently provide:

- Language-specific coding standards
- Framework-specific implementation guides
- Cloud vendor recommendations
- Database-specific optimization guidance

Companion guides may be introduced for popular technology stacks where appropriate.

---

## Automation Support

The framework currently relies on manual review and validation processes.

Future releases of the **WaysNX Development Quality Platform (DQP)** are planned to provide automation for:

- Repository analysis
- Documentation validation
- Governance compliance
- Architecture reviews
- Specification quality scoring
- Engineering dashboards

---

## Engineering Metrics

While WBF defines quality principles, it does not yet include a comprehensive engineering metrics model.

Planned capabilities include:

- Documentation completeness scoring
- Specification quality metrics
- Repository health indicators
- Engineering maturity assessment
- Architecture compliance metrics

---

## AI-Assisted Engineering

AI integration is currently limited to guidance and future planning.

Future versions may include AI-assisted capabilities for:

- Documentation review
- Specification analysis
- Requirement validation
- Architecture recommendations
- Review automation
- Quality assessment

Engineering decisions will always remain under human oversight.

# Out of Scope

The following areas are intentionally outside the scope of the current framework.

## Project Management Methodologies

WBF complements—but does not replace—project management methodologies such as:

- Agile
- Scrum
- Kanban
- SAFe
- Waterfall
- PRINCE2

Organizations should continue using their preferred delivery methodology alongside WBF.

---

## Software Development Frameworks

WBF does not prescribe specific implementation technologies.

Examples include:

- React
- Angular
- Vue
- Laravel
- Spring Boot
- .NET
- Node.js
- Django

The framework is designed to remain technology independent.

---

## Vendor-Specific Recommendations

WBF intentionally avoids recommending specific:

- Cloud providers
- Database vendors
- Hosting platforms
- CI/CD platforms
- Monitoring tools
- Commercial software products

Organizations are free to choose technologies that align with their business and technical requirements.

# Conclusion

The WaysNX Business Framework is intentionally designed to grow over time.

Its current limitations reflect conscious design decisions rather than shortcomings. By establishing a strong foundation first, WBF can evolve in a structured, maintainable, and community-driven manner.
